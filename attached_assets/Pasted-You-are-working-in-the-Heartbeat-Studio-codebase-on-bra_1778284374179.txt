ISSUES #18 #19 #21 #28 — Auth redirect sends users to dashboard instead of intended destination

File: client/src/pages/AuthPage.tsx

Root cause:
Two places say window.location.href = '/dashboard' after login — hardcoded, ignoring where the user came from.

Fix:
Replace both hardcoded dashboard redirects with a helper.

Use a safe redirect helper that only allows relative in-app paths:

const getRedirectTarget = (): string => {
  const params = new URLSearchParams(window.location.search);
  const returnTo = params.get('returnTo');

  if (returnTo && returnTo.startsWith('/') && !returnTo.startsWith('//') && returnTo !== '/auth') {
    return returnTo;
  }

  return '/dashboard';
};

Then use:

window.location.href = getRedirectTarget();

in both places:
- the isAuthenticated useEffect
- the loginSuccess useEffect

Also search the codebase for links/buttons/routes that send logged-out users to /auth from specific experiences such as Birthday Blast, Gospel Greeting, Sung Prayer, and Classroom Cheers.

If those CTAs currently route to /auth directly, update them to include a returnTo query parameter, for example:

/auth?returnTo=/birthday-blast

Use encodeURIComponent if constructing dynamically:

setLocation(`/auth?returnTo=${encodeURIComponent(targetPath)}`)

Do not change unrelated auth behavior.
